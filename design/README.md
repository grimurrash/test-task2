# Дизайн · Макеты песочницы и документации

**Роль-автор:** дизайнер · **Сессия:** 3 · **Задача:** [#10](https://github.com/grimurrash/test-task2/issues/10)
· **Журнал:** [sessions/design.md](../sessions/design.md)

## Что здесь лежит

| Файл | Что это |
|---|---|
| `tokens.css` | Дизайн-токены: палитра, типографика, отступы, состояния компонентов. **Единственный источник значений** |
| `sandbox.html` | Макет экрана песочницы — все семь состояний ответа на одной странице |
| `docs.html` | Макет страницы документации — шапка, оглавление, «Идемпотентность», curl-блок, таблицы |
| `screenshots/` | Итоговый вид обоих экранов на 1280 и 375 — для ревью без запуска и для отчёта (A5) |

## Как смотреть

Открыть `sandbox.html` и `docs.html` браузером прямо из клона — сборка не нужна.
Шрифты Inter и JetBrains Mono подтягиваются с Google Fonts при наличии сети;
без сети — молчаливая деградация в системный стек, макет остаётся рабочим.
Узкий экран проверяется сужением окна: ниже 1100px колонки складываются в столбец.

Стилевое направление — **строгий финтех** (решение сэра, сессия 3): чернильная
шапка, индиго-акцент в навигации и фокусе, журнал обмена как таймлайн с цветной
осью, сдержанные тени.

Макет — **статичная картинка поведения**, не приложение: JS-логики нет намеренно,
вёрстка песочницы — зона фронта (#12).

### Семь состояний ответа — метки C1–C7 в журнале

Серые пунктирные метки на записях журнала — аннотации макета для приёмки,
**в реализацию не переносятся**.

| Метка | Состояние | Как показано |
|---|---|---|
| C1 | 201 создан | зелёная запись, пометка «новый платёж» |
| C2 | 200 повтор | синяя запись, «тот же платёж», развёрнутое тело: тот же `id` и `created_at`, что у C1 |
| C3 | 409 конфликт тела | `idempotency_key_reuse`, приписка «существующий платёж не изменён» |
| C4 | 409 гонка | группа «две одновременные отправки»: 201 у победителя + 409 `request_in_progress`, один ключ. По контракту проигравший может получить и 200 (тот же платёж) — в макете показан исход с 409, оговорка в записи |
| C5 | 409 отмена завершённого | `payment_not_cancelable` после сценария с суммой 120,02 (…02 → succeeded) |
| C6 | 422 валидация тела | `validation_failed` в журнале (`details.errors` — все нарушения разом) **и** поле «Сумма» формы в состоянии ошибки |
| C7 | ошибка сети | пунктирная запись «нет ответа» + подсказка «безопасно повторить с тем же ключом» |

Дополнительно (вне семи состояний): группа «двойная отмена» — двa ответа 200,
отмена идемпотентна (F14); чипы `status_reason: test_amount_rule` в списке платежей (F18).

## Что берёт фронт

- `tokens.css` импортируется как есть; все значения — через `var(--…)`, ничего
  не подбирается на глаз. Имена токенов стабильны — тёмная тема, если появится,
  будет переопределением значений, не переименованием.
- Цвет зарезервирован за **смыслом**: `created` / `repeat` / `conflict` / `error` /
  `network` + статусы платежа. Кнопки нейтральные («чернильные»), индиго-акцент —
  только фокус, ссылки и активная навигация — чтобы действия не спорили со смыслом
  ответов.
- Шрифты в реализации — из npm (`@fontsource/inter`, `@fontsource/jetbrains-mono`
  или аналог), не с CDN: макет тянет Google Fonts только ради простоты просмотра
  из клона.
- Журнал — таймлайн: токены `--timeline-rail` и `--timeline-dot-size`, цвет точки —
  семантика ответа. Поле ключа и кнопка «Сгенерировать» — двумя строками, чтобы
  UUID был виден целиком; у ключа кегль `--font-size-caption`.
- `select` стилизуется под общий вид полей (`appearance: none`, своя стрелка),
  нативное фокус-кольцо браузера заменяется токеном `--focus-ring` у всех контролов.
- Оттенок точки у чипа ключа идемпотентности в реализации выводится из значения
  ключа (hash → hue); в макете — два образца (`.key-a`, `.key-b`).
- Длинный `description` в списке — обрезка по трём строкам (`line-clamp`), полный
  текст при раскрытии карточки; в журнале и формах `id` и ключи переносятся
  (`overflow-wrap: anywhere`), горизонтального скролла страницы нет.

## Края поведения, не нарисованные отдельными экранами

Ответы дизайнера на пробелы из ревью фронта — реализуются токенами, отдельные
макеты не нужны:

- **Пустой журнал / пустой список:** центрированный текст `--color-text-muted` —
  «Журнал пуст — отправьте первый запрос» / «Платежей пока нет».
- **Запрос в полёте:** кнопки «Отправить» и «Отправить ещё раз» — в состоянии
  disabled (`--button-disabled-opacity`); запись в журнале появляется по ответу,
  промежуточную запись не рисовать.
- **«Отправить ещё раз тот же запрос» до первого запроса:** disabled — повторять
  нечего.
- **400 ошибок заголовков в журнале** (ключ стёрли руками, мерчант сломан):
  тот же вид, что C6, — семантика `error` покрывает 422 и 400, бейдж с фактическим
  кодом.
- **Раскрытие карточки с длинным `description`:** снимается `line-clamp`
  (`-webkit-line-clamp: unset`), текст целиком, переносы уже заданы
  (`overflow-wrap: anywhere`).

## Сверка с контрактом (#9) — выполнена

Контракт `openapi/openapi.yaml` принят 2026-08-25; макет сверен с файлом в `main`:

- семантика 201/200 на повтор, тело `Payment`, TTL 24 ч, правило тестовых сумм
  `% 100`, изоляция по мерчанту, «новые сверху» в списке — совпали;
- **валидация тела — 422 `validation_failed`** (все нарушения разом
  в `details.errors`), 400 остался только ошибкам заголовков; в PRD это были
  `invalid_amount`/`invalid_currency` с 400 — макет приведён к контракту
  (состояние C6, таблицы `docs.html`);
- `Idempotency-Key` — 1–255 символов (уточнено в таблице заголовков).

Контракт — источник правды; при его изменении макет догоняет отдельным коммитом.
