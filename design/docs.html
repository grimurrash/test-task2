Идемпотентность

Ключ идемпотентности — это ваша страховка от двойного списания. Вы придумываете уникальную строку (обычно UUID), кладёте её в заголовок Idempotency-Key при создании платежа — и с этого момента сервер гарантирует: сколько бы раз запрос ни повторился, платёж будет один.

Правило одной строкой. Один ключ + одно тело = один платёж, сколько бы раз вы ни отправили запрос.

Что вернёт сервер

Первый запрос отвечает 201 — платёж создан. Повтор с тем же ключом и тем же телом отвечает 200 и возвращает тот же ресурс — тот же id, тот же created_at, байт-в-байт. По коду ответа клиент отличает «создал» от «вернул существующий».

Тот же ключ с другим телом — ошибка 409 idempotency_key_reuse: сервер отказывается угадывать, какое из двух тел правильное. Существующий платёж при этом не изменяется.

Два запроса одновременно — платёж всё равно один. Проигравший запрос получит либо тот же ресурс, либо 409 request_in_progress — тогда просто повторите его: придёт 200 с готовым платежом. Второй id не возникает никогда.

Сколько живёт ключ

24 часа (TTL по умолчанию). После истечения тот же ключ создаст новый платёж — поэтому ключ не переиспользуют между разными заказами, а генерируют на каждый заказ свой.

Ключи изолированы в пределах мерчанта: одинаковый ключ у разных X-Merchant-Id — это два независимых платежа.

Пример

bash 
curl -X POST http://localhost:8080/v1/payments \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 3f9c1b8e-5a02-4d67-9c11-8de402aa71f5" \
  -H "X-Merchant-Id: demo-shop-a" \
  -d '{
    "amount_minor": 149000,
    "currency": "RUB",
    "order_id": "ORD-1042",
    "description": "Подписка PRO, август"
  }'

Отправьте команду дважды: первый ответ — 201, второй — 200 с тем же id. Это и есть идемпотентность.

Тестовые суммы

Настоящих платёжных провайдеров в песочнице нет, поэтому терминальный статус задаётся правилом по последним двум цифрам amount_minor (формально: amount_minor % 100). Правило применяется синхронно при создании; если оно сработало, в ответе status_reason: "test_amount_rule".

amount_minor % 100Статус при созданииstatus_reason
1 (…01)failedtest_amount_rule
2 (…02)succeededtest_amount_rule
остальныеpendingnull

Обратите внимание: суммы 1 и 2 минорных единицы — тоже триггеры правила (1 % 100 == 1, 2 % 100 == 2). Платёж на одну копейку уйдёт в failed — это не поломка, а правило песочницы.

Заголовки

ЗаголовокОписание
Idempotency-Keyобязателен Ключ идемпотентности, до 128 символов. TTL — 24 часа
X-Merchant-Idобязателен Идентификатор мерчанта: 1–64 символа из набора [A-Za-z0-9._-]

Ответы

201 Платёж создан
200 Повтор: возвращён существующий платёж, тот же id
400 idempotency_key_required · merchant_id_required · invalid_merchant_id · invalid_amount · invalid_currency
409 idempotency_key_reuse · request_in_progress

Образец оформления: остальные три эндпоинта собираются Scalar-ом по этой же схеме — бейдж метода, путь, таблицы заголовков и ответов.
