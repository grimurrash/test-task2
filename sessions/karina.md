# Журнал координатора

Ведётся сессией-координатором по [регламенту](../docs/roles/karina.md).
Запись на каждое решение о выдаче задачи и на каждое закрытие: дословное
задание сэра, кому выдано и почему именно так, что вернулось в рапорте,
что помешало. Журнал уезжает в `main` одним pull request на смену вместе
с `REPORT.md`, а не по одному на задачу.

Форма записи:

```
## <дата> · #<номер тикета> · <Имя>-<номер тикета>

**Задание сэра (дословно):** …
**Тикет:** #N — <заголовок>
**Копия и ветка:** .worktrees/<slug>, <type>/<slug>
**Условие старта:** нет / <какое, кто следит>
**Рапорт:** <кратко: PR, CI, находки ревью, проблемы>
**Проверка факта:** gh pr view <N> → merged, gh pr checks → зелёный
**Закрыт:** <когда, с каким комментарием>
**Что помешало:** <отказы механизмов, задержки, дубли — или «ничего»>
```

### Промежуточный доклад #103 — и что из него забрано в регламент

**Состояние:** из зоны `protected-files` исполнитель вышел сам, продления
не просил: правка хуков закончена, ревью и PR пропуска не требуют. Четыре

**Ревью плана: 27 находок, 4 блокирующих.** Открылись девять форм
с `$HOME`/`~`, три с `..`, три с односегментным путём в позиции записи,

**Находка про метод — забрана в `docs/roles/executor.md`.** Дословно
от исполнителя: пары к сужениям стояли в позициях, которые продолжают

не в той позиции, выглядит полной, не будучи ею. Это общее правило
для любой правки механизма, не только для этой задачи.

**Вопрос, вынесенный сэру:** цена принятого решения — решение хука стало
