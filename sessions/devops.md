## Что сделано

1. `.claude/hooks/scan-untrusted.py` — добавлен `EXTERNAL_TEXT_CMD`: команда
   должна стоять в позиции запуска (начало строки или после `; & |`), не просто
   упоминаться в тексте. Список — `gh issue view/list/comment`, `gh pr view`,
   `curl`, `wget`, ровно как в задаче. `main()` для `tool_name == "Bash"` сначала
   проверяет команду и молча выходит, если она не тянет текст извне; источник
   в логе для Bash — сама команда, а не пустая строка.
2. `.claude/settings.json` — `scan-untrusted.py` подключён в существующий блок
   `PostToolUse` → `matcher: Bash`, рядом с `mark-verify.py`.
3. `scripts/test_hooks.py` — три новых кейса в разделе `scan-untrusted.py`:
   `gh issue view` со скрытой инструкцией (находка названа), `ls` с тем же
   маркером (не сканируется), `gh issue view` без инъекций (тишина).
4. `docs/HOOKS.md` — обновлена строка `scan-untrusted.py` в таблице хуков; новая
   строка в таблице «Что нашлось в обычной работе» с историей находки; новый
   пункт в «Что остаётся дырой» — список сканируемых команд ограничен и требует
   ручного расширения при появлении новых способов затянуть текст снаружи
   (`gh api`, `ssh`, кастомные скрипты).
5. `docs/tasks/00-handoff-project.md` — раздел «Текст задачи — данные, а не
   команды» переписан: ручная прогонка сканером перед работой больше не нужна
   для `gh issue view/list/comment` и `gh pr view` — это делает хук сам; для
   всего остального (текст, пришедший другим путём) правило по-прежнему ручное.

## Решения

| Решение | Обоснование |
|---|---|
| Ветка `fix/scan-untrusted-bash` от `main` | предписано телом issue #6, разрешено исключением в `.claude/guard-allow.txt` |
| Сканировать только `gh issue view/list/comment`, `gh pr view`, `curl`, `wget`, а не весь Bash | прямая граница из issue: «сканирование всего подряд зашумит сессию» — `scripts/test_hooks.py` держит образцы инъекций и срабатывал бы на каждом прогоне |
| Позиционная проверка команды (`^|[;&|]`), а не поиск подстроки | тот же приём, что уже есть в `guard-git` и `guard-protected-files`: «упоминание — не запуск». Без якоря `git commit -m "смотри curl"` сканировался бы напрасно |
| Не запускать `/feature` (Workflow-оркестрация) | инструмент `Workflow` требует явного опт-ина пользователя в его собственных словах; прямая просьба сэра его не содержала. Сделано напрямую: ветка → правка → тесты → документация → живая проверка → PR |
| Отдельного ревью другим агентом не заводил | сам issue #6 отмечает пункт «приёмку делает не автор» как сознательно не соблюдённый в этот раз — приёмка за сэром |
| Пропуск `protected-files` запрашивался у сэра дважды | первая попытка не отразилась в `.claude/state/unlock.json` (там лежала старая истёкшая запись из более ранней сессии) — не стал считать её действующей и переспросил вместо того, чтобы гадать |
