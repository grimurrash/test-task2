## Замер, пересчитанный после первого ревью плана

Первая редакция журнала считала только 28 воспроизводимых команд и давала
«20 настоящих против 8 ложных». Ревьюер плана показал, что выброшенная
21 усечённая — не нейтральная потеря, а самая плотная концентрация ложных.
Разобрал все 21 по тексту и по причине отказа сам: настоящая среди них **одна**
(`chmod +x scripts/unlock.sh && git add -A && git commit …` — правка
защищённого файла), остальные двадцать — чтение файла пропусков, запись
задания в чужой каталог, запуск хука с подачей JSON, цитата пути в тексте.

Пересчёт по всему журналу:

| | уникальных команд | случаев |
|---|---|---|
| всего отказов `guard-protected-files` | 49 | 1389 |
| **ложных** | **28** | **52** |
| настоящих | 21 | 1337 |
| из них — дословные фикстуры набора проверок | 8 | 944 |

По случаям настоящих в 25 раз больше, но это счёт прогонов набора, а не работы:
восемь фикстур дают 944 случая из 1337. **По уникальным командам ложных
больше, чем настоящих: 28 против 21.** Прежняя арифметика журнала (1361)
была неверна — правильное число случаев у настоящих 1337.

Точное разделение «живая работа против фикстур» до конца не сводится: старые
редакции набора отличались от нынешней, и сопоставление по дословному
совпадению даёт нижнюю оценку. Поэтому в приёмку иду с числами выше,
а не с оценкой доли живой работы.

**Ограничение замера, названное вслух.** Журнал пишет `cmd[:300]`, поэтому
21 из 49 уникальных команд (43%) воспроизвести нельзя — разбор усечённой
команды отличается от разбора целой. Число «после» меряется на 28
воспроизводимых; для усечённых показываю восстановленные представители
каждого класса. Чтобы следующий замер был сопоставим, к записи отказа
добавляются полная длина команды и её отпечаток.

## Ревью плана: две линзы, обе внешние

Отдельными агентами, ни один не писал план.

**Линза «дыры в сужении»** — восемь блокеров, все с прогоном:

1. `CLAUDE.md` без слэша в имени не проходит `_plain_candidate`, поэтому
   `rm CLAUDE.md`, `touch CLAUDE.md`, `sed -i … CLAUDE.md`, `cp /tmp/x CLAUDE.md`
   держатся **только** на слепом упоминании, которое #166 снимает.
   → `write_candidates` отдаёт позиционные аргументы пишущих команд сырьём.
2. Переменная-посредник: `f=<хук>; echo evil >> "$f"` — цель `$f`.
3. `xargs -I{} sh -c 'echo x >> {}'` — цель `{}`.
4. `eval "echo x >> <хук>"` — аргумент `eval` командной строкой не разбирается.
   → 2–4 закрываются одним правилом: **неразобранная цель записи — это
   «разобрать нельзя», а не «безопасно»**, и для такой команды слепой поиск
   упоминания остаётся.
5. Встроенный код без признака `INLINE_WRITE` (`os.system('rm …')`,
   `subprocess.run([…])`) сегодня ловится по пути, а по плану проходил бы —
   прямая регрессия. → признак записи внутри кода расширяется на формы,
   которые уходят в оболочку.
6. `ln` не как `cp`: у жёсткой ссылки правка второго конца меняет первый
   (проверено прогоном, тот же inode). → `ln` убран из «источник только читается».
7. `rm -rf .claude`, `mv .claude .claude-off`, `rm -rf .github` — тот же
   промах якоря уровнем выше. → добавлены каталоги верхнего уровня.
8. Формы вообще без признака записи: `git checkout HEAD~3 -- <хук>`,
   `git restore`, `git apply`, `tar -xzf`, `ed`; `fs.promises.writeFile`
   мимо `INLINE_WRITE`.

Замечания: `unlock.sh --list` надо проверять по токену **сразу после** имени
скрипта, иначе `bash scripts/unlock.sh protected-files 120 "правим -h"` пройдёт
и выдаст настоящий пропуск; шаблоны без `re.I` при регистронезависимой
файловой системе (`claude.md` — тот же файл); `grep -v` читается как
монтирование тома (`WRITE_INTENT`, общий с `guard-scope` — в #176).

**Линза «список и замер»** — пропущенное в списке:
`scripts/scan_untrusted.py` (рабочая часть хука лежит вне каталога хуков и при
неудаче импорта молча подменяется заглушкой), `.claude` и `.github` целиком,
`.mcp.json` (инструмент MCP не совпадает ни с одним матчером), `scripts/ci/`
и `.ci-stack`. Плюс возражение по исключению `scripts/test_hooks.py`:
моё обоснование ссылалось на экземпляр 1 из #166, а тот отказ дало `MENTION`
на каталоге хуков, а не защита самого набора. Обоснование было неверным —
набор в список включён, цена названа числом (8 коммитов из 42).

Обе линзы приняты полностью; отклонённых замечаний нет.

## Неустановленная половина #175 — закрыта прогоном

Пять прогонов на учебном проекте в `/tmp`, Claude Code 2.1.238. Полностью —
в `docs/HOOKS.md`. Коротко: наборы хуков **сливаются**; пустой `PreToolUse`

**хуки не запускались вовсе**, а блок `env` доставляет в процесс хука
`CLAUDE_HOOK_STATE_DIR` (откуда читаются разрешения) и `PATH` (чем
запускается сам хук). Ответ «не может ничего» не подтвердился: поштучно
не может, целиком — может.
