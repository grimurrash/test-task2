# Салават-148 — задача #148

Копия: `.worktrees/compose-docs-api-url`, ветка `fix/readme-docs-rebuild` (от `main`).
Координатор: сессия «Карина [2a8ba0]». Задача заведена по находке из разбора
[#102](https://github.com/grimurrash/test-task2/issues/102), вынесенной отдельно.

## Задание

[#148](https://github.com/grimurrash/test-task2/issues/148) — README объясняет
обязательность `--build` только через песочницу, хотя адрес API вшивается
на сборке и в страницу документации.

Критерии приёмки:

1. оба раздела README говорят про документацию так же, как про песочницу,
   без второго источника истины: одно правило, два сервиса;
2. проверка прогоном: с переопределённым `API_PORT` **без** `--build`
   воспроизводится описанный симптом, с `--build` адрес верный;
3. умолчание не меняется.

## Что понял и как решил

Дефект — не в коде, а в объяснении: правило «адрес вшивается на сборке»
верно для двух статических частей, а README приписывает его одной. Правка
должна не удваивать текст, а поднять правило на уровень выше обеих частей —
иначе появится второй источник истины, и следующая правка разойдётся с первой.

Отсюда форма правки:

- **§ «Если порт занят»** — одно правило на обе части: адрес вшивается
  на сборке и в песочницу, и в документацию; обе отдают готовую статику
  и конфигурацию в момент запуска не читают. Дальше два разных следствия
  одного правила, а не два правила;
- **§ «Если не поднялось»** — отдельный симптом для документации рядом
  с симптомом песочницы. Механизм здесь не повторяется, идёт ссылка
  на раздел про порты: симптомы разные, причина одна.

## Чем подтверждено — прогон, а не чтение

Прогон делался на своих портах (`19000/19001/19002`), чужие контейнеры
не трогались. Эталон: образ `psp-docs:local` собран на умолчании.

**Шаг 1 — симптом без `--build`:**

```
$ API_PORT=19000 SANDBOX_PORT=19001 DOCS_PORT=19002 docker compose up -d
--- адрес в примерах на странице документации ---
API=http://localhost:8080
--- а API на самом деле здесь ---
  http://localhost:19000/v1/payments -> 200
--- команда, скопированная со страницы, уходит на чужой процесс ---
  http://localhost:8080/v1/payments -> 200 (это не наш стенд)
```

Симптом воспроизвёлся в худшей своей форме, и это стоит назвать прямо:
на порту `8080` в тот момент жил **чужой** контейнер `psp-api` от другого
запуска. Команда, скопированная со страницы документации, вернула `200` —
успешный ответ **не от того стенда**. Ни ошибки, ни предупреждения: ровно
тот тихий отказ, ради которого заведена задача. Догадка «упадёт с connection
refused» оказалась мягче реальности — падения может не быть вовсе.

**Шаг 2 — с `--build`:**

```
$ API_PORT=19000 SANDBOX_PORT=19001 DOCS_PORT=19002 docker compose up --build -d
#17 1.043 Адрес API на странице: http://localhost:19000 (из API_BASE)
--- адрес в примерах теперь ---
API=http://localhost:19000
--- берём его прямо со страницы и стучимся ---
  http://localhost:19000/v1/payments -> 200
--- справочник ---
servers: [{ url: 'http://localhost:19000' }]
--- все адреса на странице ---
   3 http://localhost:19000
   1 http://localhost:8080
```

Оставшееся `8080` — не пример, а предупреждение о расхождении со `servers`
контракта, оно так и задумано.

**Шаг 3 — умолчание не изменилось:**

```
$ docker compose build docs --no-cache
Адрес API на странице: http://localhost:8080 (по умолчанию)
Адрес в контракте: http://localhost:8080 — совпадает
```

## Прогон проверок репозитория

```
$ python3 scripts/ci/scan_secrets.py
scan_secrets: секретов в отслеживаемых файлах не найдено (184 файлов)   rc=0

$ python3 scripts/scan_untrusted.py .
scan_untrusted: скрытых инструкций не найдено                            rc=0

$ python3 scripts/test_hooks.py
ПРОВАЛОВ: 2
    ✗ координатор закрывает тикет    ожидали allow получили deny
    ✗ своя рабочая копия открыта     ожидали allow получили deny
```

**Красное красным и называется.** Оба провала — `guard-roles` по чужому
дефекту [#147](https://github.com/grimurrash/test-task2/issues/147): `ROOT`
считается от расположения набора, внутри рабочей копии им оказывается сама
копия, и сессия видится хуку исполнителем в своей же копии. К правке README
отношения не имеют — она текстовая и `guard-roles` не касается; то же
падение независимо получил `Ранит-77`. Координатор установила порядок:
#103 с починкой прибора идёт в `main` первым, мой PR — после, с перебазированием.
Зелёным это до тех пор не называется и гейт не обходится.

## Отказы механизмов

**`guard-git` отклонил создание ветки** в форме с базой и пайпом:

```
Заблокировано хуком guard-git: создание новой ветки.
Команда: git checkout -b fix/readme-docs-rebuild main 2>&1 | tail -3 && ...
```

Исключение в `.claude/guard-allow.txt` — `git (?:checkout -b|switch -c)
(?:feature|fix|chore|docs|test)/[a-z0-9._-]+$` — с якорем `$`: команда обязана
заканчиваться именем ветки. Разложил на две отдельные (`git checkout main`,
затем `git checkout -b fix/readme-docs-rebuild`), обе прошли. Отказ верный,
не ложный: обход тут был бы в дописывании исключения, а не в разложении
собственной команды.

**Ложное срабатывание `guard-scope`** (записано и в журнале #102, передано
координатором в #103): подстрока `</code>` внутри grep-паттерна принята
за путь `/code`, read-only команда отклонена как запись наружу.

## Ревью результата — независимый агент

Проверяющий получил задание **опровергнуть** вердикт по #102, а не подтвердить
его. Итог: функциональная часть вердикта устояла, формулировка «править
нечего» — нет.

**Устояло, проверено его собственным прогоном:**

- симметрия — `API_PORT=9000 docker compose config` даёт `API_BASE:
  http://localhost:9000` и `VITE_API_BASE: http://localhost:9000`, текстуально
  одно выражение в `compose.yaml:54` и `compose.yaml:82`;
- тихого разрыва в цепочке нет, и он искал его целенаправленно: `ENV
  API_BASE=${API_BASE}` входит в ключ кэша, слой `RUN npm run build`
  перевыполняется при смене порта, устаревший образ не подсовывается;
  предупреждения `UnknownArg` на свежей сборке нет — значит аргумент реально
  объявлен и потреблён;
- краевые случаи чисты: завершающий слэш срезается (`build.mjs:40`), пустой
  `API_BASE` откатывается на умолчание, пустой `API_PORT` даёт `8080` через
  `:-` симметрично песочнице;
- покрытие `replaceAll` полное: в `scenarios.md` ровно два адреса, оба
  в полной форме, всё прочее через `$API`.

**Замечания и что с ними сделано.**

1. **`docs-site/README.md:80` — «Строку `args` вносит devops: `compose.yaml` —
   их зона. Пока её нет».** Утверждение ложно с 25 августа. Проверяющий,
   открывший README зоны документации, чтобы понять, сделан ли #102, прочтёт
   письменное «не сделан». Замечание принимаю как верное.
   **Правку не делаю, выношу координатору:** `docs-site/` — зона документации,
   и правка чужого файла внутри моего PR — ровно то, за что владелец того
   потока отказал в исходной #102. Решение о тикете за координатором.

2. **`docs-site/README.md:110-111` — зашитый `8080` в прозе про кнопку
   «Test Request».** Смысл фразы («шлёт туда же, куда curl») верен, буквальный
   адрес — нет: при `API_PORT=9000` селектор сервера показывает 9000.
   Замечание верное, судьба та же, что у первого.

3. **«Исполнитель сам себя опровергает: в копии лежит незакоммиченная правка
   README на 14 строк».** Замечание фактически точное, но вывод отклоняю
   письменно, с обоснованием. Правка — это задача #148, заведённая
   координатором **по моей же находке из разбора #102** и до того, как
   проверяющий её увидел. Вердикт звучал не «в репозитории нечего править»,
   а «по критериям приёмки #102 править нечего», и в этой границе он верен:
   все три критерия закрыты без единой правки. Находка за границей критериев
   была названа вслух, а не умолчана, — и стала отдельным тикетом, а не
   строкой в чужом PR.

4. **«Журнал `sessions/Салават-102.md` исчез из копии».** Наблюдение верное
   и полезное: ветка `fix/readme-docs-rebuild` взята от `main`, а журнал #102
   лежит в `fix/compose-docs-api-url`, которая в `main` не поедет — pull
   request по #102 не открывается. Записи грозит смерть вместе с рабочей
   копией. Вопрос вынесен координатору отдельно: перенести журнал в этот PR
   или сохранить иначе — решение её.

5. **«Под подстановкой адреса нет механизма».** Замечание принимаю как верное
   по существу и не закрываю в этой задаче. `replaceAll` — буквальная замена,
   а CI образ документации не собирает и на выживший `8080` не проверяет.
   По правилу самого проекта это пожелание, а не правило. За критерии #148
   выходит целиком; выношу координатору как кандидата в отдельную задачу.

**Что проверяющий отдельно проверил и дефектом не счёл:** `openapi.yaml:155`
остаётся `8080` даже при 9000 — сознательное решение, описанное
в `build.mjs:86-94`, расхождение закрывается блоком `spec-notice`; он убедился,
что при 9000 уведомление есть на обеих страницах, а на умолчании — нет ни
на одной. Умолчание `http://localhost:8080`, записанное в пяти местах, —
согласованная проектом константа, задаче предшествует.

Чужого проверяющий не задел: контейнер `psp-api` на `8080` не трогал,
поднимался на `9100`, за собой погасил.
