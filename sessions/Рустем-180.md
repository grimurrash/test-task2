# Рустем-180 — задача #180

## Задание (дословно, из тикета)

`[требования] шесть непокрытых хвостов: F20, U4, U7, A4, A7, A8`. Аудит показал:
50 из 56 требований PRD подтверждены прогоном полностью, 6 — частично.
Задача закрывает ровно эти шесть хвостов и ничего сверх них. Источник истины —
`docs/product/PRD.md`.

Общее правило приёмки: на каждый хвост нужен тест, **который покраснеет при
нарушении требования**. Обратную проверку исполнитель делает сам: ломает
поведение, показывает красный, возвращает, показывает зелёный; оба вывода —
в этот журнал. «Тест есть» доказательством не считается.

## Отступление от обычного цикла (решение сэра, причина — лимит токенов)

1. Ревью плана — **ровно один** агент-ревьюер вместо трёх. Codex на ступени
   ревью плана не запускается вовсе.
2. Ревью результата — **только** `codex exec review --base main -o <вердикт>`.
   Агентов-ревьюеров на этой ступени ноль.

Что не отменяется: пустой / упавший по таймауту / `unavailable` вердикт codex —
это **отсутствие внешней линзы**, а не «чисто»; так и пишется в PR и в рапорт.
Замечание codex нельзя проигнорировать молча: либо правка, либо письменный отказ
с обоснованием.

## Разбор задания

Вердикт: **задание выполнимо, противоречий с PRD не нашлось**. Что понято:

- **F20** (`docs/product/PRD.md:141`) — три полосы тела: до 1 МБ разбирается,
  1–8 МБ дочитывается и отбрасывается с целым ответом 400, выше 8 МБ соединение
  рвётся. Сейчас тестом закрыта только средняя граница
  (`backend/test/validation.test.ts:401`, тело ~2 МБ), `MAX_DRAIN_BYTES`
  (`backend/src/app.ts:34`) не упомянут ни одним тестом.
- **U4** (`PRD.md:174`) — сценарий гонки в песочнице. Оба исхода (`201/200`
  и `201/409`) законны; закреплять надо инвариант, а не код ответа.
- **U7** (`PRD.md:178`) — изоляция значений сервера от bidi-символов. Сейчас
  `unicode-bidi: isolate` есть только на `.chip` (`frontend/src/app.css:269`)
  и `<bdi>` только в журнале (`frontend/src/components/Journal.tsx:48`);
  в списке платежей `order_id` и `description` не изолированы.
- **A4** (`PRD.md:233`) — «все границы раздела 5 покрыты тестами» без механизма.
  Раздел 5 даёт **43** требования: F1–F22 с подпунктами (25), U1–U7 с U4a (8),
  D1–D4 (4), R1–R6 (6). A-критерии — раздел 6, в перечень не входят.
- **A7** (`PRD.md:236`) — контрактная сверка не смотрит заголовки. Схемы
  `XMerchantId` / `IdempotencyKey` / `PaymentId` через валидатор не проходят ни разу.
- **A8** (`PRD.md:237`) — прогон на чистом клоне повторить нечем.

Проверено при разборе: **контракт набор символов ключа идемпотентности не
сужает** — у `IdempotencyKey` в `openapi/openapi.yaml` только `minLength: 1` и
`maxLength: 255`, `pattern` нет. То есть опасение тикета (молчаливая отмена
починки #75 из PRD F7c) сегодня не подтверждается; сверка заголовков это
зафиксирует механизмом.

## Обратная проверка 1 · F20 (`backend/test/body-limits.test.ts`)

Пять проб, прижатых к самим константам: 900 КБ, ровно `MAX_BODY_BYTES`,
`MAX_BODY_BYTES + 1`, ровно `MAX_DRAIN_BYTES`, `MAX_DRAIN_BYTES + 1`.

**Зелёный на целом коде:**

```

**Красный, поломка 1 — предел дочитывания снят**

```

**Красный, поломка 2 — дочитывания нет вовсе**
(`const MAX_DRAIN_BYTES = MAX_BODY_BYTES;`): соединение рвётся сразу
за пределом разбора, ответ 400 до клиента не доходит.

```
not ok 1 - @req F20 на байт выше предела разбора — 400 malformed_request
not ok 2 - @req F20 тело ровно в предел дочитывания: ответ пришёл целиком, соединение не оборвано
# tests 5
# pass 3
# fail 2
```

**Возврат (`git checkout backend/src/app.ts`) — снова зелёный:**

```
# tests 5
# pass 5
# fail 0
```

Замечание ревьюера, которое здесь сработало: проба выше 8 МБ обязана нести
валидные `X-Merchant-Id`, `Idempotency-Key` и `Content-Type`. Без них сервер
ответил бы раньше чтения тела, Node всё равно порвал бы недочитанное
соединение — и тест был бы зелёным по чужой причине, включая случай со снятым
пределом. Поэтому проба идёт через `app.create`, а не через `app.raw`.

### Чего сделать не удалось, и почему — это не «всё хорошо»

**Полный прогон на чистом клоне (исход 0) и прогон со сломанной приёмкой
(исход 1) в этой среде выполнить нельзя.** Демон Docker здесь не тянет образы:

```
docker pull docker/dockerfile:1        завис, прерван на 45-й секунде
node:22-alpine, nginx:1.29-alpine      в локальном кеше отсутствуют
psp-backend:local                      отсутствует (пересобрать нечем)
```

Сеть до реестра с хоста при этом есть (`https://registry-1.docker.io/v2/` →
401, обычный ответ для анонима), то есть упирается именно демон.

Что это значит по-честному: **требование тикета «вывод прогона приложен к PR»
по этому хвосту не выполнено.** Скрипт написан, разобран и проверен в трёх
своих отказных путях, но заявить «инструкция README работает на чистом клоне»
я не могу — этого прогона не было. Заготовка для исхода 1 (клон с приёмкой,
ждущей заведомо чужой id) делалась и удалена: без поднятого стенда она
бессмысленна.

Прогон, который закрывает хвост целиком, — одна команда на машине, где Docker
тянет образы:

```
bash scripts/clean-clone-check.sh
```

Вынесено в PR отдельной строкой и в рапорт координатору.
