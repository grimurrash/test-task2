# Салават-102 — задача #102

Копия: `.worktrees/compose-docs-api-url`, ветка `fix/compose-docs-api-url`.
Координатор: сессия «Карина [2a8ba0]».

## Задание

Тикет [#102](https://github.com/grimurrash/test-task2/issues/102) — «[обвязка]
compose передаёт адрес API песочнице, но не документации». Требуется
симметричная песочнице строка: сервису `docs` передаётся build-аргумент
с адресом API, собранным из той же переменной порта.

Критерии приёмки из комментария координатора:

1. симметрия с песочницей — адрес из той же переменной, теми же правилами,
   без второго источника истины;
2. проверка прогоном: сборка с переопределённым портом даёт страницу, где
   примеры указывают на этот порт, а не на зашитый `8080`;
3. умолчание не меняется.

## Разбор — что нашлось до первой правки

**Работа уже сделана, и сделана до выдачи задачи.** Строка стоит в `compose.yaml`
с 25 августа, коммит `1d21040` «feat(devops): адрес API передаётся в сборку
документации» — он сам подписан «Задача #102»:

```yaml
  docs:
    build:
      context: .
      dockerfile: docs-site/Dockerfile
      args:
        API_BASE: "http://localhost:${API_PORT:-8080}"
```

Парная половина (#85) слита тоже: `docs-site/Dockerfile` объявляет `ARG API_BASE`
и пробрасывает его в `ENV`, `docs-site/build.mjs` читает `process.env.API_BASE`,
подставляет адрес в `servers` рендера Scalar и заменяет им умолчание в тексте
сценариев. Цепочка `API_PORT → compose args → ARG → ENV → build.mjs → статика`
замкнута целиком.

Задание не противоречиво и не дырявo — оно **выполнено**. Вердикт координатору:
работа не начинается, потому что делать нечего, а не потому что что-то мешает.
Придумать себе правку ради pull request по этой задаче — подмена задачи.

## Чем подтверждено — прогон, а не чтение

Сборка с переопределённым портом:

```
$ API_PORT=9000 docker compose build docs
#14 6.264 Адрес API на странице: http://localhost:9000 (из API_BASE)
#14 6.264 Адрес в контракте: http://localhost:8080 — расходится, предупреждение показано
```

Что реально легло в образ:

```
$ docker run --rm --entrypoint sh psp-docs:local \
    -c "grep -o 'API=http://localhost:[0-9]*' /usr/share/nginx/html/scenarios.html"
API=http://localhost:9000

$ ... grep -o "servers: \[{ url: '[^']*'" /usr/share/nginx/html/index.html
servers: [{ url: 'http://localhost:9000'
```

Полный стенд на переопределённых портах, адрес взят **со страницы** и по нему
сделан запрос к живому API:

```
$ API_PORT=9000 SANDBOX_PORT=9001 DOCS_PORT=9002 docker compose up --build -d
$ curl -s http://localhost:9002/scenarios.html | grep -oE 'http://localhost:[0-9]+' | sort | uniq -c
   1 http://localhost:8080
   3 http://localhost:9000
адрес из примера: http://localhost:9000
  GET $API/v1/payments -> 200
```

Единственное оставшееся `8080` — не пример, а предупреждение о расхождении
со `servers` контракта; оно так и задумано:

```
<p class="spec-notice">
  Стенд поднят на <code>http://localhost:9000</code>. В скачанном
  <code>openapi.yaml</code> поле <code>servers</code> указывает на
  <code>http://localhost:8080</code>: контракт описывает API, а не ваш стенд.
```

Умолчание не тронуто:

```
$ docker compose build docs
#14 2.662 Адрес API на странице: http://localhost:8080 (по умолчанию)
#14 2.662 Адрес в контракте: http://localhost:8080 — совпадает
```

Все три критерия приёмки выполнены на текущем `main`, без единой правки.

## Смежная находка — за критериями приёмки

Симметрия достигнута в `compose.yaml`, но **не в README**. Раздел «Если порт
занят» объясняет обязательность `--build` только через песочницу:

> адрес API вшивается в песочницу **на сборке** … Без пересборки песочница
> продолжит стучаться на прежний порт

Теперь то же верно и для документации, а её отказ тише: песочница хотя бы даёт
CORS в консоли браузера, документация же молча покажет неверный адрес в примерах,
и читатель скопирует команду, уходящую на чужой процесс. Раздел «Если не
поднялось» описывает симптом только песочницы.

В критерии приёмки #102 это не входит. Расширять scope самовольно не стал —
вынес координатору решением.

## Отказы механизмов

**Ложное срабатывание `guard-scope`.** Команда чтения живой страницы отклонена:

```
Заблокировано хуком guard-scope: изменение файлов за пределами репозитория.
Путь: /code
Команда: ... curl -s http://localhost:9002/scenarios.html | grep -oE 'API=http://localhost:[0-9]+|http://localhost:[0-9]+</code>' ...
```

Хук принял подстроку `</code>` внутри grep-паттерна за путь `/code` и счёл
read-only команду записью наружу. Никакой записи в команде нет: `curl` без `-o`,
`grep`, `cut`. Обошёл переформулировкой своего паттерна, а не обходом хука.
