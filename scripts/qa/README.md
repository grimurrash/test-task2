# Обвязка ломателя API

Пробы, которыми ломался HTTP API в задаче #15 (журнал — `docs/reviews/breaker-api.md`).
Снаружи сервиса, только через публичные интерфейсы. Продуктовый код не трогают.

## Запуск

Поднять API из известного коммита на своём порту (**не** на общем `:8080` —
там состояние в памяти, общее для всех) и указать его в `BASE`:

```bash
cd backend && npm ci && npm run build && PORT=8123 node dist/src/index.js &
cd scripts/qa && BASE=http://localhost:8123 node p2-routes.mjs
```

Скрипты запускаются из `scripts/qa`. `BASE` по умолчанию — `http://localhost:8123`.

| Файл | Что проверяет |
|---|---|
| `lib.mjs` | обёртка над `fetch`: создание платежа, разбор ответа |
| `contract.mjs` | **сверка любого тела ответа со схемами `openapi.yaml`** через `ajv` — тем же способом, что набор бэкенда, но снаружи; этим найден #74 |
| `p1-cors.mjs` | `Access-Control-*` на всех классах ответа + preflight на произвольных путях |
| `p2-routes.mjs` | методы и маршруты, `Allow`, сверка тел ошибок со `schemas/Error` |
| `p3-key-bytes.sh` | длина `Idempotency-Key`: символы против байтов (#75) |
| `p4-invariants.mjs` | порядок списка, 409-reuse без мутации платежа, один ключ у двух мерчантов |
| `p5-pipeline-order.mjs` | порядок при **совпадающем** `created_at` — конвейер запросов в одном сокете |
| `p6*.sh`, `p6b-*.mjs` | тело на методах без тела; сравнение `curl` и `fetch`-клиента |
| `p7-inject.mjs` | засев скрытых инструкций в `description`/`order_id` (проверка сканера, #77) |
| `p8-dup-key.sh` | дублирующийся `Idempotency-Key` (#73) |

## Чего обвязка не умеет

TTL ключа и окно `request_in_progress` снаружи не наблюдаемы — нужен контроль
времени и задержка в критической секции. Нагрузка и DoS вне объёма. Песочница
и браузер — не сюда.

## Две грабли, купленные временем

Обе давали **ложное «устояло»**, пока не были пойманы:

1. **`undici` не отправляет не-ASCII заголовок вовсе** — `fetch` с кириллическим
   `X-Merchant-Id` или `Idempotency-Key` падает на стороне клиента, до сервера
   ничего не доезжает. Не-ASCII заголовки проверяются только `curl`-ом или сырым
   сокетом (`p3-key-bytes.sh`).
2. **Тело ответа приходит по частям (chunked)**, потому что сервер не ставит
   `Content-Length`. Самодельный парсер сокета молча возвращает `undefined` — и
   проверка начинает сравнивать собственные `undefined`, показывая зелёное.
   В `p5-pipeline-order.mjs` из-за этого первая версия печатала «доехало: да»,
   не получив от сервера ни одного значения; значения берутся из ответа API
   (списка), а не из разбора сокета.

Отсюда правило журнала: у каждой итерации есть колонка **«доехало»** — чем
доказано, что атака достигла проверяемого места. «Устояло» без неё не пишется:
барьер, сработавший раньше цели (клиент, валидация, среда, компилятор), проверяет
барьер, а не сервис.
