# Хуки: правила, переведённые в механизм

На первом занятии агент удалил папку, хотя в `CLAUDE.md` было написано не удалять.
Разбор свёлся к формулировке: «она была мягкой». Это половина причины. Вторая —
словесный запрет действует ровно до первого текста, который окажется убедительнее.

Поэтому здесь правила живут не в прозе, а в коде. Всё, что описано ниже, проверено
запуском: `python3 scripts/test_hooks.py` — 27 проверок.

## Что стоит

| Хук | Событие | Что делает |
|---|---|---|
| `guard-secrets.py` | PreToolUse: Bash, Read, Grep, Glob, Write, Edit | Блокирует обращение к `.env`, `~/.ssh`, `~/.aws`, ключам, глобальным настройкам Claude Code, `sudo` |
| `guard-git.py` | PreToolUse: Bash | Блокирует force-push, `--no-verify`, `filter-branch`, удаление защищённых веток. Переспрашивает на прямой push в `main`, `reset --hard`, создание ветки, worktree |
| `guard-scope.py` | PreToolUse: Bash, Write, Edit | Блокирует запись и удаление за пределами репозитория |
| `guard-protected-files.py` | PreToolUse: Write, Edit | Требует подтверждения на правку `.claude/`, `.github/workflows/`, `CLAUDE.md` |
| `scan-untrusted.py` | PostToolUse: Read, WebFetch, WebSearch | Ищет скрытые инструкции в прочитанном и называет их вслух |
| `mark-verify.py` | PostToolUse: Bash | Фиксирует факт прогона тестов и анализаторов |
| `gate-quality.py` | Stop | Не даёт закрыть сессию с незакоммиченным кодом или без прогона тестов |
| `session-start.sh` | SessionStart | Печатает приоритет инструкций, проверяет целость обвязки, линтует `CLAUDE.md` |

## Почему не хватило permissions

Правило `deny` — это шаблон на строку команды. Запрет `cat secrets.txt` не мешает
прочитать тот же файл через Python. Проверка в `scripts/test_hooks.py` ровно это
и воспроизводит: `python3 -c "print(open('.env').read())"` получает отказ, потому
что хук смотрит на упоминание пути, а не на имя команды.

Уточнение к тому, что звучало на занятии: `deny`-правила действуют во всех режимах,
включая `bypassPermissions`; отключаются только `allow` и `ask`. Поэтому в
`.claude/settings.json` лежат оба слоя — и `deny`, и хуки.

## Как ослабить запрет

Регулярка в `.claude/guard-allow.txt` снимает блокировку по совпадению с командой
или путём. По одной строке на случай, с комментарием зачем. Не «разрешить всё».

## Что остаётся дырой

- Песочница Claude Code накрывает Bash и его дочерние процессы, но **не MCP**.
  Хуки перехватывают вызовы инструментов, но подключённый MCP-сервер со своими
  правами — отдельный разговор.
- `guard-scope` разбирает команду регулярками, а не полноценным парсером shell.
  Изощрённая конструкция с подстановкой пути через переменную его обойдёт.
- Хуки живут в репозитории и применяются, когда сессия открыта **в этой папке**.
  Сессия из другой директории их не подхватит.

Это записано здесь, а не умолчано, потому что защита с неизвестными границами
хуже, чем защита с известными.

## Журналы

- `.claude/logs/guard.jsonl` — каждый отказ и каждый запрос подтверждения
- `.claude/logs/untrusted.jsonl` — найденные скрытые инструкции
- `.claude/state/verify.json` — когда и чем в последний раз проверяли код

Оба журнала в `.gitignore`: это рабочее состояние машины, а не история проекта.
Для отчёта они выгружаются отдельно.
