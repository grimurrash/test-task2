# Требования без исполняемого теста

Этот файл — вторая половина сверки покрытия (критерий A4, задача #180).
Первая половина — пометка `@req <ID>` в имени теста. Требование раздела 5 PRD,
у которого нет ни пометки, ни строки здесь, **красит прогон**:
`backend/test/requirements-coverage.test.ts` читает оба источника.

Зачем файл вообще нужен. Часть требований раздела 5 говорит не о поведении
кода, а о доставке: страница документации, подъём стенда, порты, образы.
Проверка вида «в `README.md` есть нужное слово» осталась бы зелёной при
сломанном `docker compose up` — то есть была бы проверкой, которая выглядит
проверкой (REPORT 4.1). Такие требования стоят здесь, с названным механизмом
и названной ценой, а не прикрыты пометкой на тесте-декорации.

**Строка здесь — не освобождение.** Это заявление: чем требование
подтверждается на самом деле и почему это не входит в `npm test`. Пустая
причина или ссылка на несуществующее требование красит прогон так же, как
отсутствие теста.

| # | Чем подтверждается | Почему не тестом прогона |
|---|---|---|
| D2 | сборка образа `docs` (`docker compose build docs`): страница собирается из `openapi/openapi.yaml`, копии контракта внутри `docs-site/` нет | проверяется сборкой контейнера, а не кодом; тест «в `build.mjs` есть слово SPEC» зеленел бы на сломанной сборке |
| D4 | `docs-site/tools/extract.mjs` + `run.mjs` + `verify.mjs`: примеры страницы гоняются живьём против поднятого API и сверяются с обещанием блока, в двух проходах | нужен поднятый стенд; статическая сверка «блок бьёт по описанному маршруту» к тому же ложно красная — страница намеренно показывает несуществующий маршрут и чужой метод (`docs-site/src/scenarios.md`, раздел «Отказы, которые стоит увидеть заранее»), это демонстрация F19 |
| R1 | `scripts/clean-clone-check.sh`: клон, `docker compose up -d --build`, три части отвечают | требует Docker и несколько минут сборки; в прогон тестов такое не кладут |
| R2 | `scripts/clean-clone-check.sh` поднимает стенд на своих портах через переменные окружения, файлы не правит | то же: проверяется подъёмом, а не чтением файла |
| R3 | `docker compose run --rm backend-test` вместе с `backend/Dockerfile`: рантайм-цель собрана без `node_modules` и без исходников тестов, поэтому запустить их в ней нельзя | требование о содержимом образа; изнутри прогона образ не виден |
| R4 | `docker compose run --rm backend-test` — та самая команда из требования; её вывод прикладывается к каждому PR | прогон не может подтвердить сам факт своего запуска в контейнере |
| R5 | `scripts/clean-clone-check.sh` идёт по README буквально: предусловия, запуск, проверка работоспособности, остановка | «раздел в README существует» — не то же, что «инструкция работает»; работает она только на чистом клоне |
| R6 | `scripts/clean-clone-check.sh` и раздел README «Состояние живёт в памяти»: перезапуск обнуляет состояние | проверяется перезапуском контейнера, а не кодом |

## Что здесь стоять не должно

Требование, для которого тест написать можно. Если строка появилась ради
зелёного прогона — это возврат к утверждению вместо проверки, ровно то, что
критерий A4 и закрывает.
