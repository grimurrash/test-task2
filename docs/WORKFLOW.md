# Workflow `/feature`

Повторяемая процедура для любой задачи, доходящей до кода и до pull request.
Файл: [`.claude/workflows/feature.js`](../.claude/workflows/feature.js).

## Запуск

```
/feature Добавить идемпотентность в создание платежа
```

Или напрямую, если нужно задать ветку и slug:

```
Workflow({ name: "feature", args: { task: "...", slug: "idempotency", base: "main" } })
```

## Ступени

| # | Ступень | Кто делает | Что остаётся на диске |
|---|---|---|---|
| 1 | План | один агент | `docs/plans/<slug>.md` |
| 2 | Ревью плана | три независимых агента: архитектура, риски, объём | вердикты в журнале прогона |
| 3 | Правка плана | один агент сводит замечания | обновлённый план + раздел «Отклонённые замечания» |
| 4 | Реализация | один агент по утверждённому плану | ветка `feature/<slug>`, коммиты, тесты |
| 5 | Ревью результата | две линзы Claude (корректность, тесты) плюс внешний ревьюер на codex | список дефектов с пометкой, чья линза нашла |
| 6 | Исправления | один агент | коммиты с исправлениями |
| 7 | MR | один агент | pull request через `gh pr create` |
| 8 | CI | один агент | вердикт по проверкам, разбор падений |

Ступени 2–3 крутятся до двух раундов: пока остаются замечания уровня `blocker`
или `major`, план возвращается на правку.

## Три решения, которые здесь зашиты

**Ревьюеров трое, и у каждого своя линза.** Три одинаковых проверяющих находят
одно и то же. Архитектура, риски и объём — разные вопросы к одному тексту.

**Проверяет не автор.** Ступени 5–6 отданы агентам, которые код не писали. Автор
не бывает независимым проверяющим — он проверяет то, что имел в виду, а не то,
что написал.

**Третий проверяющий — другой вендор.** Субагент видит контекст родительской
сессии: это приближение к независимой проверке, а не она сама. Поэтому третья
линза ступени 5 уходит наружу — в `codex exec`, read-only, со структурированным
вердиктом по `.claude/schemas/review.json`. Обёртка: `scripts/review_codex.py`.

Если codex не установлен, не авторизован или не уложился в срок, обёртка
возвращает `verdict: unavailable` с причиной. Workflow при этом не падает,
но пишет в лог и в тело PR, что проверка осталась внутримодельной. Молча
деградировать до «сам себя проверил» — худший из возможных исходов.

**Замечание нельзя проигнорировать молча.** На каждое — либо правка, либо
письменное обоснование отказа в плане. Молчание не считается ответом.

## Что нужно до запуска

- `gh` установлен и авторизован: `gh auth status`. Ступень 7 останавливается
  сама и возвращает точную команду, если авторизации нет.
- `codex` установлен и авторизован: `codex login status`. Без него ступень 5
  теряет внешнюю линзу, но не останавливается.
- Ветка `main` чистая, работа начинается от неё.

Проверить внешнего ревьюера отдельно, без всего workflow:

```bash
python3 scripts/review_codex.py "Проверь .claude/hooks на способы обхода запретов"
```

## Чего workflow не делает

Не мержит. Ступень 8 доводит до зелёного CI и останавливается — решение
о слиянии принимает сэр.
