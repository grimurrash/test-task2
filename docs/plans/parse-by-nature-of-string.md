# План: разбор по природе строки (issue #103)

Ветка `fix/parse-by-nature-of-string`. Правится один файл — `.claude/hooks/_paths.py`,
на него нужен пропуск в зону `protected-files`. Набор проверок — `scripts/test_hooks.py`,
названные ограничения — `docs/HOOKS.md`; ни то, ни другое пропуска не требует.

## Диагноз

Разбор снимает кавычки **до** токенизации (`path_candidates` → `normalize` →
`translate(QUOTES)`), после чего лексер режет получившееся по пробелам и знакам
пунктуации. С этого места строка теряет природу: содержимое кавычек, тело
встроенного кода и аргументы командной строки становятся одним потоком токенов,
и правило, верное для одного, применяется ко всем.

Все девятнадцать отказов `guard-scope` за 26 августа объясняются этим одним
местом:

| Что было в команде | Во что превратилось после снятия кавычек |
|---|---|
| `grep -o "…<code>[^<]*</code>"` | токен `/code` |
| `echo "=== / ==="` | токен `/` |
| `awk '/^worktree /{print $2}'` | токен `/^worktree` |
| `(b-a).total_seconds()/60,` | токен `/60,` (скобки — знаки пунктуации лексера) |
| `os.environ['M']` … `()/M` | токен `/M` |
| `grep -rl "feature.js\|/feature"` | токен `/feature` |

Ни одна из этих строк не является путём оболочки. Каждая — своей природы:
литерал в кавычках, программа awk, выражение внутри встроенного кода.

## Решение: природа определяется структурой, а не содержимым

Четыре природы, каждая со своим правилом:

| Природа | Откуда берётся | Правило |
|---|---|---|
| **путь оболочки** | токен командной строки | позиция известна: имя команды, ключ, операнд, цель перенаправления |
| **содержимое встроенного кода** | аргумент `-c`/`-e`/`-r`, программа `awk`, тело документа для интерпретатора | путь живёт **внутри строкового литерала**; снаружи — выражение |
| **чужая файловая система** | стадия `docker`/`podman` | уже разбирается, чинится только достижимость перенаправлений |
| **литерал с экранированием** | `$'…'`, `$"…"` | `$` снимается, дальше обычный литерал |

Первая половина решения даётся даром: **не снимать кавычки до токенизации**.
`shlex` в posix-режиме сам снимает их по токену и при этом сохраняет границу —
содержимое кавычек остаётся ОДНИМ токеном. Пять из шести строк таблицы выше
после этого перестают быть кандидатами: они становятся одним относительным
токеном, который разрешается внутрь репозитория.

## Правки в `_paths.py`

### 1. Кавычки не снимаются до токенизации

`path_candidates` перестаёт звать `normalize` (та стирает кавычки) и работает
с текстом после `strip_heredocs` и снятия `$` перед кавычкой. Сам `normalize`
не меняется: его зовут `guard-secrets` (как сено для регулярок) и `resolve`
(на одиночный путь) — там снятие кавычек уместно.

Цена и её проверка: `echo x > "/outside/file"` обязан остаться отказом.
`shlex` в posix-режиме снимает кавычки внутри токена, поэтому кандидат тот же.

### 2. `$'…'` — литерал, а не имя переменной

`re.sub(r"\$(?=['\"])", "", text)` в `normalize` и в предтокенизации
`path_candidates`. Без этого `rm -rf $'/outside'` даёт токен `$/outside`,
который перестаёт быть абсолютным и приклеивается к корню репозитория —
путь наружу становится «внутренним» (пункт 2 задачи).

Названная цена: escape-последовательности внутри (`$'\x2f'`, `$'\057'`)
не раскрываются. Раскрывать их значит писать собственный разбор ANSI-C —
и получать вторую реализацию правил оболочки. Пишется в `docs/HOOKS.md`.

### 3. Перенаправления с приставкой и хвостом

- `REDIRECT_OPS = {">", ">>", ">|", "&>", "&>>", ">&"}` вместо сравнения ровно
  с `>` и `>>` в сборе целей — иначе `docker ps &> /outside/file` не даёт
  кандидата (пункт 3 задачи);
- в `WRITE_INTENT` запрет цифры перед `>` снимается: `(?<![0-9<>])` →
  `(?<![<>])`. Без этого `echo x 2> /outside/file` выходит из хука раньше
  разбора — то есть до правки #97 дело просто не доходит.

Замер лексера (подтверждён запуском): `2>` даёт токены `2` и `>`, `&>` и `>|`
приходят одним токеном, `2>>` — `2` и `>>`.

### 4. Содержимое встроенного кода разбирается по литералам

Новая таблица: какой аргумент какой команды является кодом и какой природы.

- `sh`, `bash`, `zsh`, `ksh`, `dash`, `ash`, `fish`, `csh` с `-c` → **оболочка**,
  разбирается рекурсивно теми же правилами (это сохраняет отказ на
  `sh -c 'chmod -R 777 / 2'`);
- `python*`, `node`, `deno`, `bun`, `perl`, `ruby`, `php`, `osascript`, `lua`,
  `Rscript`, `tclsh`, `pwsh` с `-c`/`-e`/`-r`/`--eval` → **код**;
- `awk`, `gawk`, `mawk` — первый позиционный аргумент → **код**;
- тело документа, отданного интерпретатору, — той же природы, что интерпретатор.

Правило для природы «код»:

1. из текста вынимаются строковые литералы (`'…'`, `"…"`, `'''…'''`, `"""…"""`,
   `` `…` ``);
2. литерал, состоящий из **одного** токена, — путь целиком, кандидат без
   оговорок: `open('/newfile','w')` остаётся отказом;
3. литерал из нескольких токенов разбирается **как командная строка оболочки** —
   это сохраняет отказ на `os.system('chmod -R 777 / 2')` и заодно снимает
   отказ на строке документации, где `/karina` стоит среди слов;
4. вне литералов кандидатом остаётся только абсолютный путь **не короче двух
   сегментов** (`/outside/file`) или относительный, начинающийся с точки
   (`../outside/x`). Односегментный `/слово` и голый `/` снаружи литерала —
   это деление, регулярное выражение или знак пунктуации лексера.

Пункт 4 — замена гипотезе координатора «`/<цифры>` — деление». Гипотеза верна
по следствию, но не по причине: `/60,`, `/M`, `/^worktree` объединяет не то,
что там цифры, а то, что все они стоят **снаружи литерала** и появились от
резки по скобкам. Правило по литералу структурное и закрывает шире, оставаясь
на стороне отказа: многосегментный путь вне литерала (`perl -e "unlink
q(/outside/x)"`) кандидатом остаётся.

### 5. Односегментный токен вне позиции цели записи

Гипотеза координатора №1, беру как есть. В природе «путь оболочки» токен
вида `/слово` (ровно один сегмент) **не** считается кандидатом, если
одновременно:

- он не стоит целью перенаправления (`>`, `>>`, `2>`, `&>`, `>|`);
- он не является аргументом команды из `FS_COMMANDS`;
- такого пути нет на диске.

Голые `.` и `..` — то же правило без проверки существования (она для них
бессмысленна): кандидат, только если это цель перенаправления или аргумент
файловой команды. Это закрывает отказ на `cd ..` внутри многостадийной команды.

Пары обязательны в обе стороны:

- `echo x > /newfile` — отказ (цель перенаправления, файла ещё нет);
- `grep -c /newfile docs/x.md > docs/y.md` — проходит;
- `rm -rf /1`, `rm -rf /42` — отказ (аргумент файловой команды);
- `cp docs/x.md ..` — отказ; `cd .. && npm test` — проходит.

### 6. Получатель документа — команда своей стадии

`heredoc_body_is_data` берёт `command_word` от **всех** токенов строки, то есть
имя первой стадии. У `mkdir -p docs/roles && cat > docs/roles/executor.md <<'MD'`
это `mkdir`, а получатель документа — `cat`. Тело не вырезается, и текст,
который команда пишет в файл, проверяется как команда: два ложных отказа
из девятнадцати отсюда.

Правка: искать стадию, в которой стоит `<<`, и брать имя её команды. Запрет
на конвейер (`cat <<'EOF' | bash` — тело исполняет `bash`, а не `cat`)
остаётся, но сужается: тело считается данными, если **все** стадии ниже по
конвейеру — из списка заведомо не исполняющих stdin (`tail`, `head`, `wc`,
`grep`, `sort`, `uniq`, `tr`, `cut`, `jq`, `tee`, `sed`, `cat`, …). Незнакомая
команда ниже по конвейеру оставляет тело под проверкой.

Пара: `gh pr create --body-file - <<'BODY' 2>&1 | tail -3` проходит;
`cat <<'EOF' | bash` с удалением наружу — отказ.

## Чего этот план не делает

**Пункт 4 задачи** (`tar -C`, `unzip -d`, `openssl -out`, `dd of=`,
`find -delete`, `docker build -o`) выведен координатором в отдельный тикет
#108 комментарием от 26 августа. Все шесть форм воспроизведены и по-прежнему
проходят; в этой ветке они не чинятся. Если решение изменится — отдельная
правка, а не довесок к этой.

**Разбор оболочки парсером.** `shlex` — лексер: он не знает группировки,
подоболочек и приоритетов. План опирается только на то, что лексер даёт
надёжно: границы слов, кавычки, комментарии, операторы. Это записано в шапке
модуля до меня и остаётся верным.

## Названные ограничения — в `docs/HOOKS.md`

Правило проекта: ненадёжное различение не чинится, а называется. По итогам
этой правки в раздел «Что остаётся дырой» идут четыре строки:

1. `$'…'` без раскрытия escape-последовательностей (правка 2);
2. одиночный литерал-путь во встроенном коде проверяется всегда — даже когда
   это данные. Скрипт, перечисляющий пути как данные (`print(['/karina'])`),
   получит отказ. Позицию внутри кода определить нельзя, и отказ здесь дешевле
   пропуска;
3. односегментный `/слово`, которого нет на диске, вне позиции цели записи
   не проверяется (правка 5). Незнакомая команда, пишущая туда своим ключом,
   пройдёт. Создание записи в корне требует прав root, и цена принята
   сознательно;
4. и отдельной строкой — общий вывод, который просил записать координатор:
   за один вечер трижды выяснилось, что защита не неверна, а **недостижима**.
   Ранний выход открывался лишним совпадением подстроки внутри флага
   (`--rm`), не открывался нужным глаголом (`tar`, `find`) и обходился формой
   присваивания (`dd of=`). Самый аккуратный разбор бесполезен, если до него
   не доходит управление.

## Как проверяется

`python3 scripts/test_hooks.py` — из рабочей копии. К существующим кейсам
добавляются пары на каждое проявление; плюс **зафиксированный набор из
девятнадцати настоящих команд** 26 августа с ожидаемым решением по каждой:
восемнадцать `allow`, одна `deny` (запись в `~/.claude/.../memory/` — там
граница сработала верно и обязана срабатывать дальше).

### Прибор — issue #147, чинится в этой же ветке

Набор красный из рабочей копии ещё до всякой правки: два кейса `guard-roles`,
причина — `ROOT` считается от `scripts/..`, а внутри копии это сама копия,
лежащая в `.worktrees/`. Координатор завёл #147 и решил чинить здесь же:
без правки прибора #103 не сдаётся по собственным критериям приёмки.

Правка — только в `scripts/test_hooks.py` (не защищённый файл), хук не трогаю:
кейсам `guard-roles` подаётся синтетический корень, не зависящий от того,
откуда запущен набор.

Условия приёмки, поставленные координатором:

- набор зелёный **из обеих точек** — из основной копии и из рабочей;
- парная половина сохранена: сессия с `cwd` внутри `.worktrees/<имя>`
  по-прежнему получает отказ на `gh issue close` и на чужую копию. Правка
  прибора, снимающая проверку, приёмку не проходит.
