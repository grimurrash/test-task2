# План: что защищено и как это решается (issue #175 и #166)

Ветка `fix/protected-files-scope`. Правятся два файла под пропуском в зону
`protected-files` — `.claude/hooks/guard-protected-files.py` и
`.claude/hooks/_paths.py`; набор проверок `scripts/test_hooks.py` и
`docs/HOOKS.md` пропуска не требуют.

Порядок задан координатором: сначала #175 (дыра), затем #166 (трение).
Отдельный коммит на тикет.

## Диагноз

Два тикета — две половины одного механизма.

**#175, список.** `PROTECTED` перечисляет пути с якорем `$` на конце имени
файла либо со слэшем на конце каталога. Оба якоря дают один класс промахов:
из списка выпадает сосед, чьё имя длиннее на сегмент, и сам каталог, когда
его трогают целиком. Замерено прогоном: мимо проходят
`.claude/settings.local.json`, `CLAUDE.local.md`, `.claude/state/verify.json`,
а также `rm -rf .claude/hooks` и `rm -rf .github/workflows`.

**#166, разбор.** Хук задаёт команде два независимых вопроса —
«есть ли в ней признак записи» (`WRITE_INTENT` по всей строке) и «упомянут ли
в ней защищённый путь» (`MENTION` по всей строке) — и отказывает на совпадении
ответов. Связи между ними нет. Поэтому `rm` по файлу в `/tmp` плюс `git diff`
по хуку читается как «команда правит сами хуки».

Семь из восьми ложных отказов боевого журнала — ровно эта развязка. Восьмой
(`unlock.sh --list`) — свой: запуск скрипта пропусков считается выдачей
пропуска независимо от режима, хотя `--list` только печатает открытые зоны.

## Решение #175: список описывает семью файлов, а не одно имя

Шаблоны — в том виде, в каком они стоят в коде. Таблица первой редакции плана
описывала якоря `(?:^|/)…(?:$|[/.])`; ревью результата показало прогоном, что
левый якорь ломает второе применение списка — упоминание пути внутри
встроенного кода, где перед путём стоит кавычка или скобка, а не слэш.
Левого якоря нет нигде, кроме `CLAUDE.md` и `.mcp.json`: у них в шаблоне нет
каталога, и без ограничения слева под них попал бы всякий `МОЙCLAUDE.md`.

| вид | шаблон | что покрывает |
|---|---|---|
| файл | `<путь>(?:\.[\w\-]+)?\.<расш>(?:$|[^\w\-])` | сам файл, его именованных соседей (`settings.local.json`) и суффиксные формы (`.bak`, `.tmp-1234`) |
| каталог | `<путь>(?:$|[^\w\-])` | и содержимое, и сам каталог: `rm -rf`, `mv` |
| каталог верхнего уровня | `\.claude/?(?:$|[^\w\-./])` | только сам каталог; содержимое ловят шаблоны выше |

Сверка идёт без учёта регистра (`re.I`): файловая система здесь
регистронезависимая, и `echo x >> claude.md` пишет в `CLAUDE.md`.

Список после пересмотра и правило членства — в `docs/HOOKS.md`, раздел
«Список защищённых путей: обе ошибки — про якоря». Там же названо, что
сознательно не добавлено и почему, и цена включения набора проверок числом.

**Парная половина.** Расширение списка не должно запретить чтение. К `Read`,
`Grep` и `Glob` хук не подключён, но правило теперь держится на самом хуке
(`READ_ONLY_TOOLS`), а не на строке матчера в настройках, которую правит
соседняя задача. На каждый новый путь стоит пара «правится — отклоняется,
читается — проходит», а на два из них ещё и пара «без пропуска отклоняется,
с пропуском проходит».

**Неустановленная половина закрыта прогоном** — см. тот же раздел
`docs/HOOKS.md`. Коротко: поштучно локальные настройки слой хуков не
ослабляют, но ключ `disableAllHooks` выключает его целиком, а блок `env`
доставляет в процесс хука `CLAUDE_HOOK_STATE_DIR` (откуда читаются
разрешения) и `PATH` (чем запускается сам хук).

## Решение #166: признак записи привязывается к пути

В `_paths.py` добавляется **новая** функция `write_candidates(command)` —
рядом с `path_candidates`, не вместо неё. `path_candidates` отвечает на вопрос
«какие пути в команде названы», `write_candidates` — «в какие из них команда
пишет». `guard-scope` продолжает пользоваться первой и своего поведения
не меняет: граница репозитория считает всякое обращение наружу записью,
и это её осознанный выбор.

Целью записи считается:

| позиция | пример | почему |
|---|---|---|
| цель перенаправления | `> f`, `>> f`, `2> f` | пишут туда |
| позиционный аргумент команды из `FS_COMMANDS` | `rm f`, `mv a b`, `touch f` | у `mv` и `rm` **все** позиционные — цели: источник исчезает |
| **последний** позиционный у `cp`, `rsync`, `scp`, `install`, `ln` | `cp a b` | источник только читается |
| файловые аргументы `sed -i` / `perl -i` | `sed -i '' s/x/y/ f` | правка на месте |
| аргумент ключа вывода | `curl -o f` | признак записи назвал его поимённо |
| позиционные у `git clone/init/worktree add`, `patch` | | уже перечислены в `WRITE_TARGET_SUBS` |
| источник тома контейнера без `:ro` | `-v /host:/cont` | контейнер пишет в каталог хоста |
| **всё, что названо внутри встроенного кода с признаком записи** | `python3 -c "open('CLAUDE.md','w')…"` | разобрать нельзя — см. границу ниже |

Хук после правки:

```
цели = write_candidates(команда)
для каждой цели: если защищённый путь → отказ или пропуск

если встроенный код И в нём есть признак записи:
    старый поиск упоминания по всей команде  ← граница сохраняется
```

**Граница, которая не снимается.** Встроенный код (`python3 -c`, документ,
отданный интерпретатору) разобрать надёжно нельзя. Если в нём есть признак
записи (`INLINE_WRITE`), упоминание защищённого пути **где угодно в команде**
по-прежнему считается записью. Снимается только слепой поиск упоминания
в обычной команде — там, где позиция аргумента известна.

**`unlock.sh --list`.** `RUN_UNLOCK` сужается: режимы, которые ничего не
выдают (`--list`, `--help`, `-h`, запуск без аргументов — печать справки),
проходят. `--revoke` остаётся под отказом: расширять список разрешённых
режимов дальше необходимости незачем.

## Цена сужения, названная заранее

- `cp .claude/hooks/guard-git.py /tmp/backup.py` после правки **проходит**:
  источник у `cp` только читается. Дыры не открывает — обратная команда
  (`cp /tmp/backup.py .claude/hooks/guard-git.py`) остаётся отказом, а читать
  файлы правил и сегодня можно.
- Команда из незнакомой программы, пишущей по позиционному аргументу
  (`openssl -out`, `dd of=`, `tar -C`), целью записи не считается — это
  issue #108, общий предмет для всех трёх хуков, и здесь он не решается.
  Названо в `docs/HOOKS.md`.

## Как проверяется

Каждое сужение стоит **парой** в `scripts/test_hooks.py`: рядом с «безобидное
проходит» — «настоящая правка того же файла в той же форме по-прежнему
отклоняется». Формы правки перечислены отдельно, как требует приёмка #166:
файловый инструмент, перенаправление, `sed -i`, встроенный код.

1. восемь ложных отказов боевого журнала — прогон до и после, цифрой;
2. двадцать настоящих отказов того же журнала — все обязаны остаться отказами;
3. новые пути из #175 — по четыре формы правки на каждый плюс чтение;
4. `python3 scripts/test_hooks.py` целиком — зелёный.

## Неустановленная половина #175

Тикет прямо требует ответить прогоном, а не рассуждением: **что именно
локальные настройки могут изменить в слое хуков.** Проверяется отдельным
проектом в `/tmp`: два файла настроек, каждый со своим хуком, и запуск
`claude -p` в этом каталоге — по следам видно, сливаются наборы хуков или
один заменяет другой, и достижимо ли через локальный файл отключение.
Ответ «не может ничего» законен, если он получен прогоном. Результат
попадает в `docs/HOOKS.md` и в комментарий к тикету.
