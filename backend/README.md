# backend — API идемпотентного платежа

Реализация `openapi/openapi.yaml`. Контракт — источник правды: ответы сервиса
проверяются против его схем прямо в тестах.

## Запуск

```bash
npm ci
npm run build        # сборка рантайма (без тестов)
npm start            # http://localhost:8080, порт меняется переменной PORT
```

## Проверки

```bash
npm test             # тесты node:test + сверка ответов с контрактом
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
```

`npm test` читает `openapi/openapi.yaml` из соседней папки репозитория. Путь
переопределяется переменной `OPENAPI_PATH`; отсутствие файла — громкий отказ,
а не тихий пропуск проверки соответствия.

## Docker: две цели сборки

R3 («в рантайме нет исходников тестов и devDependencies») и R4 («`npm test`
работает в контейнере») в один образ не помещаются: образ без тестов тесты
не запустит. Поэтому целей две.

```bash
docker build backend/                                        # цель runtime, по умолчанию
docker build -f backend/Dockerfile --target test backend/    # образ для прогона тестов
```

В `runtime` нет ни тестов, ни `node_modules`: рантайм-зависимостей у сервиса
ноль, поэтому оставлять там нечего.

### Чего цель `test` ждёт от compose

Контракт в образ не кладётся — он общий артефакт репозитория, а не часть
бэкенда. Цель `test` ждёт его монтированием:

```yaml
  backend:
    build:
      context: ./backend
      target: test          # для R4: docker compose run --rm backend npm test
    volumes:
      - ./openapi:/app/openapi:ro
    environment:
      OPENAPI_PATH: /app/openapi/openapi.yaml
      PORT: 8080
    ports:
      - "8080:8080"
```

Для рантайма цель — `runtime` (или просто без `target`), монтирование контракта
не нужно.

## Устройство

| Файл | Что внутри |
|---|---|
| `src/app.ts` | HTTP-слой: маршруты, CORS, разбор тела, конверт ошибок |
| `src/service.ts` | сценарии: создание, чтение, отмена, список |
| `src/store/memory-store.ts` | хранилище в памяти и **захват ключа идемпотентности** |
| `src/domain/payment.ts` | ресурс, правило тестовых сумм, отпечаток тела |
| `src/domain/validation.ts` | границы заголовков (400) и тела (422) |
| `src/domain/errors.ts` | коды ошибок и конверт 5.4 |

Главное место — `MemoryStore.reserve`: проверка ключа и его захват идут **без
единого `await` между ними**. Наивная версия «проверил — записал» разваливается
ровно в этом промежутке; тест `test/idempotency.test.ts` на две одновременные
отправки написан до реализации и проверен мутацией — на наивной схеме краснеет.

Данные живут в памяти (R6): перезапуск обнуляет состояние, это ожидаемое
поведение песочницы.

## Предел размера тела — граница, названная вслух

Тело запроса разбирается до **1 МБ**. Больше — 400 `malformed_request`.

Отвечать отказом, пока клиент ещё загружает тело, HTTP/1.1 позволяет, но
браузер и `fetch` в этот момент пишут в сокет и получают обрыв вместо ответа:
«сервис отверг запрос» становится неотличимо от «сервис упал». Поэтому тело
сверх предела **дочитывается и отбрасывается** — ответ уходит целым.

Дочитывание тоже ограничено: **8 МБ**. Выше этой черты соединение рвётся,
и клиент получает обрыв. Это сознательный размен: дочитывание перестаёт быть
вежливостью к клиенту и становится расходом канала по его требованию.
Контракт эту границу не описывает — она относится к развёртыванию, не к API.
