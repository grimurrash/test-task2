# Чек-лист проверки страницы

Что прогонять перед тем, как сказать «страница работает». Список короткий
намеренно: каждый пункт здесь появился после того, как что-то из него однажды
не поймалось.

## 1. Сборка

```bash
npm ci && npm run build
```

Смотреть на счётчики в выводе: число операций и кодов ошибок должно совпадать
с контрактом. Сборка падает сама, если в контракте появился код, нигде,
кроме перечня, не объяснённый, — но счётчики стоит прочитать глазами: они
показывают, что страница собрана из **того** контракта, который вы правили.

## 2. Обе ветви адреса

```bash
npm run build                                   # ожидается адрес по умолчанию
API_BASE=http://localhost:18110 npm run build   # ожидается подставленный адрес
```

В обоих случаях проверить `dist/scenarios.html` и `dist/index.html`: адрес
в примерах, `servers` в конфигурации рендера и наличие (или отсутствие)
предупреждения `spec-notice`. Условная отрисовка — две дороги, и показать
одну легче, чем обе.

## 3. Прогон примеров — дважды

Команды берутся **из собранной страницы**, а не из `src/scenarios.md`:
проверять надо то, что скопирует читатель.

```bash
node tools/extract.mjs                     # блоки из dist/scenarios.html
node tools/run.mjs first.txt
node tools/run.mjs second.txt
node tools/compare.mjs first.txt second.txt
```

Сравнение — машинное, а не глазами: глаз сверяет то, куда смотрит, а смотрит
он туда, где ждёт разницу. `compare.mjs` возвращает ненулевой код, если хоть
один блок ответил по-разному.

**Условие:** блок, который во втором проходе отвечает не тем, что обещает
страница, — сломанный блок, даже если в первом проходе он зелёный.

Правило обязательно для блоков, **создающих или потребляющих состояние
стенда**; для остальных не вредно, но и не обязательно. Признак — не код
ответа: `400` на длинный ключ не зависит ни от чего, а `409
idempotency_key_reuse` держится целиком на соседнем блоке, хотя оба отказы.

### Разметка блоков страницы сценариев

| Блоки | Роль |
|---|---|
| создание с `$KEY`, `$PAYMENT_ID`, `$DONE_ID`, экзотический ключ, суммы-триггеры | **создают** состояние |
| повтор → 200, 409 `idempotency_key_reuse`, статус, чужой мерчант, отмена, список, дубль ключа | **потребляют** состояние |
| маршрут (404/405), отсутствующие заголовки, длинный ключ, битый JSON, невалидные поля | ни от чего не зависят |

## 4. Самостоятельность блока

Отдельный вопрос, двойным прогоном не проверяемый: **что вернёт блок, если
выполнить только его**. Читатель редко проходит страницу целиком — он копирует
тот блок, который решает его задачу сейчас.

Блоки-потребители в одиночку отвечают не то, что обещано (шаг 3 без шага 1
вернёт 201 вместо 409). Это допустимо, но обязано быть сказано на самой
странице, а не только здесь: читатель чек-листа не видит.

## 5. Глазами

Открыть обе страницы и посмотреть: таблицы контракта не разъехались,
кириллица цела, консоль без ошибок, сетевой лог — только свой хост
(страница обязана работать без интернета), ширина 390 px не ломает вёрстку.

## 6. Образ

```bash
docker build -f docs-site/Dockerfile -t psp-docs .
docker run --rm -p 8082:8082 psp-docs
```

Проверить, что в рантайме нет ни `node`, ни `node_modules` — только nginx
и статика.
